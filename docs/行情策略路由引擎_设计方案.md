# 行情→策略→方向 自动路由引擎 — 设计方案

> **定位**：将手册中的三层框架（大盘→板块→个股）升级为「行情类型驱动、策略自动路由」的可执行系统。
> **核心思想**：旧思路是"一套波段打天下，不同行情调参数"；新思路是"不同行情 → 不同策略族 + 不同板块方向 + 不同买卖姿势"，代码在盘后自动完成判断。
> **设计原则**：先判天气、再选航道、最后才挑船。盘后判断，盘中只执行。
> **状态**：设计方案 v1.0，待决策者审查。

---

## 二、模块设计

### 模块①：大盘打标签 → 门控档位（Gate 0~3）

**输入数据**（全部已有）：
- 九指数日线行情（腾讯）→ 涨跌比、均值、大小盘剪刀差
- L1 持续性缓存（已实现跨日对比）
- 周线 20 周线方向（Tushare weekly）
- 量能：成交额 vs 近5日/20日均量（Tushare daily_basic）
- 情绪：涨停/跌停/炸板率（东财 limit_list 或 Tushare）
- 涨跌家数/广度（东财或同花顺）

**Gate 链**（次序固定，任一层不过即停止）：

| Gate | 名称 | 规则 | 不通过后果 |
|------|------|------|-----------|
| **Gate 0** | 周线一票否决 | 沪深300 周线 < 20周线 且方向向下 | 仓位上限 20%，停止开新仓 |
| **Gate 1** | 指数趋势三档 | 沪深300 vs MA60/MA250 的关系 | 趋势市→放行；震荡市→降级；熊市→关闭 |
| **Gate 2** | 量能与广度 | 连续3天 > 5日均量 + 上涨家数 > 2500 | 未放量的"站上MA20"=存量博弈，不按进攻档 |
| **Gate 3** | 情绪温度计 | 涨停 > 100→不再开新仓；跌停 > 10→减半；热点占比 > 30%→拥挤 | 反向过滤器，过热时降档 |

**输出：四档门控结论**：

| 档位 | 打分 | 仓位上限 | 执行指令 |
|------|------|----------|---------|
| **进攻** | 4~5分 | 80% | 策略全开，突破/回踩买点正常执行 |
| **试错** | 2~3分 | 30%~50% | 只做1~2条主线内的龙头/中军 |
| **收缩** | 0~1分 | ≤20% | 只维护观察池，不追突破 |
| **空仓** | 负分 | 0% | 不执行任何买点 |

### 模块②：行情类型判定（12种 + 6种叠加标签）

**判定逻辑**（基于手册 §4）——不是并列选择，而是按优先级的决策树：

```
输入：门控档位 + 广度数据 + 主线数据 + 情绪数据 + 风格数据
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
         普涨？           结构性？         普跌？
    (上涨家数>2500    (主线连续3~5日    (下跌家数占优
     且连续3日        走强+梯队完整      +真实跌停>10
     且持续放量)      且非主线无表现)    连续≥3日)
         │                │               │
    ┌────┴────┐     ┌────┴────┐     ┌────┴────┐
   全面性普涨 权重行情  结构性行情 风格行情  全面性普跌 防御性行情
   (广度好)  (指数红但  (主线清晰) (大小盘   (广度差)  (红利领涨)
             下跌多)             分化明显)
         │                │               │
    ┌────┴────┐     ┌────┴────┐     ┌────┴────┐
   情绪确认：   情绪确认：   情绪确认：  情绪确认：
   涨停50~100  涨停扩散    跌停>10    连板压缩
   =主升期     =加速期     =恐慌      =冰点
```

**具体12种类型+判定条件**（手册4.1~4.12）：

| # | 行情类型 | 核心判定条件 | 优先级 |
|---|---------|-------------|--------|
| 1 | **全面性普涨** | 上涨家数 > 2500~3000 连续3日 + 多指数同步 + 量能连续3日 > 5日均量 | 第一（先排除最极端） |
| 2 | **全面性普跌** | 下跌家数占优连续3日 + 真实跌停 > 10 + 多指数同向走弱 | 第一 |
| 3 | **结构性行情** | 1~3条主线连续强3~5日 + 梯队完整 + 非主线股无表现 | 第二（最常见） |
| 4 | **存量博弈震荡** | 均线缠绕 + ADX < 20 + 量能无持续放大 + 板块轮动指纹 | 第二 |
| 5 | **风格行情** | 大小盘/价值成长剪刀差连续 ≥ 3日显著 | 叠加型，可与其他共存 |
| 6 | **权重行情** | 指数红但下跌家数 > 上涨家数 + 白线在上"鳄鱼口" | 叠加型 |
| 7 | **板块轮动** | 昨日领涨今日不在前五 + 强势股次日无溢价 | 叠加型 |
| 8 | **超跌反弹** | 乖离极值 + 恐慌天量 + 反弹缩量未放量 | 第三 |
| 9 | **抱团行情** | 龙头不断新高但上涨家数/中位数一般 | 第三 |
| 10 | **防御性行情** | 涨幅前五全是银行/石油/煤炭/公用事业 | 第三 |
| 11 | **题材/事件** | 涨停集中在单一概念 + 无产业逻辑支撑 | 第四（波段回避） |
| 12 | **反转/修复** | 止跌收敛 + 放量承接 + 回踩守住 | 第四（按修复段处理） |

**叠加规则**：同一时段可贴多个标签。标签变更需连续3~5日证据，盘中不改判。

### 模块③：策略路由器（行情类型 → 策略族）

**这是整个引擎的核心**。不再像旧系统那样"什么行情都用波段打"，而是按行情类型自动路由到最合适的策略族。

#### 路由决策树

```
行情类型判定后：
│
├─ 全面性普涨 ───► 趋势跟踪（拿住，MA20止盈）+ 顺势波段（降低做段频率）
├─ 结构性行情 ───► 顺势波段（主场：主线内回踩买、冲高卖）
├─ 存量博弈震荡 ─► 区间波段/均值回归（高抛低吸）
├─ 风格行情 ───► 波段（只在占优风格内）+ 动量轮动（风格ETF）
├─ 权重行情 ───► 权重股本身的段（振幅10%，降低预期）
├─ 板块轮动 ───► 分歧低吸 + 低位启动（不追高潮，连续大涨两天不追）
├─ 超跌反弹 ───► 修复段轻仓（≤2成，碰压力就走）
├─ 抱团行情 ───► 龙头首次缩量回踩MA10（唯一买点，止损最快）
├─ 防御性行情 ──► 配置框架/红利策略（不用波段框架）
├─ 题材/事件 ──► ✗ 波段不参与
├─ 全面性普跌 ──► ✗ 空仓观察
└─ 反转/修复 ──► 试错仓起步，确认后升级
```

#### 策略族详细参数（行情相关自动调整）

| 策略族 | 买点规则 | 止盈规则 | 止损规则 | 持仓周期 | 仓位上限 |
|--------|---------|---------|---------|---------|---------|
| **趋势跟踪** | 突破买点正常执行；回踩MA20加仓 | 移动止盈：跌破MA20减半/MA60清仓；吊灯止损3×ATR | 结构失效或-8% | 2周~数月 | 50%~80% |
| **顺势波段** | 主线内回踩MA10/MA20企稳买；分歧日低吸 | 主动止盈：+15%卖1/3，+30%卖1/3；放量滞涨全走 | 结构失效或-5%~8% | 数天~数周 | 20%~40% |
| **区间波段** | 箱体下沿/均线支撑缩量企稳买；不追突破 | 箱体上沿/中轨到了就卖，至少卖一半 | 放量跌破箱体下沿/前低 | 数天~数周 | ≤50% |
| **均值回归** | Z≤-2 + 缩量企稳（ETF/蓝筹优先） | 回归到20日均线/布林中轨清仓 | Z≤-3无企稳/ADX升破25 | 数天~数周 | ≤20%（个股减半） |
| **修复段轻仓** | 止跌阳线/低开高走长下影后试仓 | 反弹至5日线减1/3→10日线减1/3→20日线清 | 跌破止跌阳线最低点 | 数天 | ≤20% |
| **配置/红利** | 按红利策略框架（股息率+估值分位），不是波段买点 | 按配置框架（再平衡、止盈） | 按配置框架 | 数月~年 | 配置仓 |

#### 旧系统 vs 新系统 对比

| 场景 | 旧系统行为 | 新系统行为 |
|------|-----------|-----------|
| 全面性普涨 | 仍用波段手法频繁高抛 | 自动切换趋势跟踪：降低做段频率，跌破MA20才减 |
| 防御性行情（红利领涨） | 用波段框架去找"超跌"红利股 | 识别为"波段✗"，切换为配置框架或不出手 |
| 存量博弈震荡 | 突破买点照做，频繁止损 | 自动禁用突破买点，只用回踩+高抛低吸 |
| 板块轮动（热点1~3天一换） | 追主线、次日就被轮换掉 | 自动降级：只做分歧低吸，不追高潮 |
| 全面性普跌 | L1 防御信号→空仓（已有） | 保持一致，同时标记观察"谁先抗跌" |
| 抱团行情 | 按普通波段做，止损不够快 | 唯一买点=龙头首次缩量回踩MA10，止损无条件最快 |

### 模块④：板块路由器（行情类型 + 策略 → 板块方向）

**不同行情下，该做哪类板块是定死的，错了就是风格错配。**

| 行情类型 | 该做的板块方向 | 绝对不碰的方向 | 板块选择逻辑 |
|---------|---------------|---------------|-------------|
| **全面性普涨** | 主线 + 扩散板块都行 | 无特别禁忌，但别频繁换 | 动量排名前5均可 |
| **结构性行情** | 只在1~2条主线板块内做（龙头+中军） | 非主线全部丢弃 | 主线五条件逐条核对 |
| **存量博弈震荡** | 只做最强方向的回踩低吸 | 追突破、弱势板块"抄底" | 最强板块分歧日承接 |
| **风格行情** | 只在占优风格内 | 跑输先查风格错配 | 大小盘/价值成长剪刀差 |
| **权重行情** | 银行、保险、运营商本身的段 | **中小盘题材**（权重涨时它们在阴跌） | 权重板块内部轮动 |
| **防御性行情** | 红利、银行、公用事业—用**配置框架** | 高弹性题材（胜率天然低） | 涨幅榜前五判别 |
| **超跌反弹** | 最先抗跌转强的板块（记入观察池） | 还在地板上的弱势板块 | 抗跌+率先转强 |
| **板块轮动** | 分歧日低吸承接、低位启动 | 连续大涨两天以上的板块 | 昨日领涨今日不在前五=轮动指纹 |
| **全面性普跌** | **不买**，只观察谁先抗跌 | 所有 | 观察池维护模式 |
| **抱团行情** | 抱团核心板块本身 | 非抱团板块（资金不会扩散） | 龙头首次缩量回踩 |
| **题材/事件** | ✗ 波段不参与 | 所有 | — |
| **反转/修复** | 率先企稳+放量+回踩守住的板块 | 仍在创新低的板块 | 止跌→低点稳定→收复路径 |

**判别口诀（代码化）**：
- 涨幅榜前五全是石油、煤炭、银行 → 市场在防守，当天极难赚钱 → 不发买入建议
- 领涨的是科技/消费方向 → 进攻日 → 可以做波段

### 模块⑤：仓位计算器（门控 × 行情类型 × 策略 × R体系）

**公式**：
```
总仓位上限 = Gate档位输出（80/50/30/0） × 行情类型折扣 × 策略类型折扣
单笔风险 = 总资金 × 1%
买入股数 = (总资金 × 1%) ÷ (买入价 − 止损价)
```

**行情类型对仓位的二次折扣**（手册附录B）：

| 行情类型 | Gate进攻档 | Gate试错档 | Gate收缩档 | Gate空仓档 |
|---------|-----------|-----------|-----------|-----------|
| 全面性普涨 | 80% | 不适用 | 不适用 | 不适用 |
| 结构性行情 | 不适用 | 30%~50% | 不适用 | 不适用 |
| 存量博弈震荡 | 不适用 | 不适用 | ≤20% | 不适用 |
| 超跌反弹 | 不适用 | ≤20% | ≤20% | 0% |
| 全面性普跌 | 不适用 | 不适用 | 不适用 | 0% |

**注**：Gate档位已是综合判断的结果，行情类型折扣只是同一档内再细分。实现时以Gate输出为主，行情类型作为策略和方向的切换信号。

## 三、每日运行流程（盘后15分钟自动执行）

```
python scripts/market_router.py   （新文件，盘后一键运行）

执行流程：
┌──────────────────────────────────────────────────┐
│ Step 1: 拉取九指数实时行情（腾讯）                   │
│ Step 2: 计算涨跌比/均值/剪刀差、读取L1缓存做持续性对比  │
│ Step 3: 拉取周线（Tushare weekly）→ Gate 0 周线否决   │
│ Step 4: 拉取量能 + 广度 → Gate 2 量能广度检查          │
│ Step 5: 拉取情绪数据 → Gate 3 情绪温度                │
│ Step 6: 综合 Gate 0~3 → 输出门控档位                  │
│ Step 7: 门控档位 → 行情类型判定（决策树）              │
│ Step 8: 行情类型 → 策略路由器 → 输出策略族             │
│ Step 9: 行情类型 + 策略 → 板块路由器 → 板块方向        │
│ Step 10: 板块方向 + 策略 → 个股筛选举荐               │
│ Step 11: 综合输出 → 每日决策报告（终端+JSON）          │
│ Step 12: 保存今日L1数据供明日持续性对比                │
└──────────────────────────────────────────────────┘
```

【Gate 门控】
  Gate 0 周线: 沪深300 周线在20周线下 ↓ → ⚠ 否决！仓位≤20%

  Gate 2 量能: 成交额 7580亿 vs 20日均量 8920亿 → 缩量
  Gate 3 情绪: 涨停32/跌停67 → 恐慌，真实跌停>10 ⚠
  
  🚨 门控结论: 空仓档（Gate 0 否决 + Gate 3 恐慌）
  仓位上限: 0%

【行情类型】
  判定: 全面性普跌 + 防御性行情（叠加）
  证据: 九指数0涨9跌，上证-1.54%/创业板-7.69%/科创-7.2%
        涨幅前五: 食品饮料+2.14%/家电/银行/公用事业/煤炭
        大小盘剪刀差 6pct → 风格极致切换
        真实跌停67只 → 恐慌

【策略路由】
  → 策略族: ✗ 空仓观察（不做任何策略）
  → 理由: 全面性普跌 + 防御行情叠加，波段坟场

【板块方向】
  → 该做的板块: 无（空仓）
  → 观察池: 食品饮料、家电（率先抗跌，等企稳后再看）
  → 绝对不碰: 通信、半导体、电子（暴跌主力）

【个股建议】
  → 今日无买入建议
  → 观察池维护: 记录今日抗跌板块内的龙头/中军，等市场企稳

【次日预案】
  → 不开新仓，条件单全部暂停
  → 观察: 下跌家数是否收敛、是否出现放量承接
  → 等"止跌收敛+放量承接+回踩守住"三件套同时出现再考虑试错
```

```
scripts/

### 7.2 防御性←→进攻性 自动判别

```python
# 涨幅前五判别：全是否银行/石油/煤炭/公用事业 → 防御日
DEFENSIVE_SECTORS = {"银行", "保险", "石油", "煤炭", "公用事业", "运营商", "电力"}

def is_defensive_day(top5_sectors):
    """涨幅前五全是防御板块 → 市场在防守"""
    return all(s in DEFENSIVE_SECTORS for s in top5_sectors)

def is_offensive_day(top5_sectors):
    """领涨的是科技/消费 → 进攻日"""
    OFFENSIVE_SECTORS = {"电子", "计算机", "传媒", "通信", "半导体", 
                         "军工", "汽车", "新能源", "食品饮料", "家电"}
    return any(s in OFFENSIVE_SECTORS for s in top5_sectors[:2])
```

### 7.3 板块轮动三大指纹检测

```python
def is_rotation_market(yesterday_top5, today_top5, yesterday_leaders_today_perf):
    """存量博弈板块轮动的三大指纹"""
    fingerprint_1 = not any(s in today_top5 for s in yesterday_top5)  # 昨天前五今天不在
    fingerprint_2 = yesterday_top5[0] in today_bottom5  # 昨天领涨今天垫底
    fingerprint_3 = yesterday_leaders_today_perf <= 0  # 强势股次日无溢价
    return sum([fingerprint_1, fingerprint_2, fingerprint_3]) >= 2
```

## 八、风险与边界

### 8.1 不做的

- **不实时盘中切换策略**——所有策略切换在盘后完成，盘中只执行盘前设定
- **不预测行情**——只"识别当前处于什么行情"，不做"明天会不会变"
- **不机器学习黑箱**——所有判定规则可解释、可审计、可人工推翻
- **不自动下单**——输出是"建议"和"条件单预设"，最终由人确认

### 8.2 关键约束

- 标签变更需连续3~5日证据，单日不翻转
- 周线一票否决权高于一切日线信号
- 策略切换规则事先写死在 `ROUTE_TABLE`，盘中不临时换系统
- 门控在空仓/收缩档时，板块再强也只维护观察池

### 8.3 已知数据盲区

| 盲区 | 影响 | 应对 |
|------|------|------|
| 梯队完整度（龙头/中军/补涨） | 主线五条件之一无法自动判定 | 标记为"需人工确认" |
| 昨日强势股今日溢价 | 轮动指纹判断 | 用同花顺/Tushare连板数据近似 |
| 北向资金（2024.8起不披露） | 资金面辅助信号缺失 | 已用5级降级链处理 |
| 板块成交占比 > 30% | 拥挤度反向指标 | Tushare ths_daily 可算 |

## 十、决策要点（请你确认/选择）

在动手写代码之前，以下几个设计决策需要你拍板：

1. **路由表的严格程度**：一致性和灵敏度是矛盾的。
   - A) 保守版：普涨判定需涨跌家数差>2000且连续3日（更少误判，但可能错过早期机会）
   - B) 标准版：涨跌家数差>1000且连续3日（手册默认阈值）
   - C) 激进版：涨跌家数差>500或连续2日（A股牛短熊长，防漏报）

2. **策略切换的响应速度**：行情变了多久才切策略？
   - A) 次日盘前切换（安全，但可能慢一拍）
   - B) 盘中实时切换（快，但与"盘中不分析"原则冲突）
   - **建议A**，与手册"标签变更需连续3~5日+盘中不改判"的纪律一致

3. **个股池来源**：L3 个股层目前只覆盖9个周期资源板块。
   - A) 先用现有9板块 + RPS过滤 → 快速出MVP
   - B) 扩展覆盖全市场 → 但个股基础数据采集成本高
   - **建议A先做MVP**，等路由引擎稳定后再扩展

4. **输出形式**：
   - A) 终端彩色输出（与现有 screen_three_layers.py 一致）
   - B) 飞书推送（与 daily_feishu_report.py 风格一致）
   - C) 两者都做
   - **建议C**，终端用于调试，飞书用于日常
