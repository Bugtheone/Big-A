## 二、WSL + VSCode 开发环境

1. Windows VSCode 装扩展：`WSL`、`Python`、`Ruff`（已装，含依赖 pylance/debugpy）
2. 连接：WSL 终端 `cd /home/dev/grok_code && code .`，或 VSCode 内 "WSL: Connect to WSL"
3. 解释器：项目 `.vscode/settings.json` 已指向 `dsa_env`（该目录 gitignored，不入库）
4. 依赖：`pip install -r requirements.txt -r requirements-dev.txt` + `pre-commit install`

## 三、网络与代理（重点，踩坑多）

- **clash 在 Windows 宿主 7897 端口**；WSL 网关 IP 会变：
  ```bash
  GW=$(ip route | awk '/default/{print $3}')
  git config --global http.proxy "http://$GW:7897"
  git config --global https.proxy "http://$GW:7897"
  ```
- **git 凭据**：`credential.helper=store`（PAT 存 `~/.git-credentials`，chmod 600；撤销=删文件）
- **DNS 污染**：`vsassets.io` 等扩展市场域名被解析到非微软 IP → VSCode 需走 clash 代理（`http.proxy=127.0.0.1:7897`）；GitHub https 直连被墙，一律经代理
- **westock npx**：如 npx 挂起，用 `env npm_config_proxy= npm_config_https_proxy= NO_PROXY='*' npx -y westock-data-skillhub@1.0.5 <命令>`

## 四、Grok Build 配置（`~/.grok/config.toml`）

| 配置面 | 值 |
|---|---|
| 模型 | 仅 DeepSeek API（`deepseek-v4-flash` 默认 / `deepseek-v4-pro` 推理）；fork=deepseek-v4-pro（无 x.ai） |
| MCP | `codegraph`（`codegraph serve --mcp`，代码结构查询）、`headroom`（`headroom mcp serve`，长文本压缩） |
| 权限 deny | `Bash(rm -rf *)` / `Bash(crontab -r*)` / `Bash(git push -f*)` / `Bash(git push --force*)` / `Bash(rm -r config/*)` |
| Hooks | `~/.grok/hooks/`：SessionStart / PostToolUse（工具审计→`~/.grok/logs/tool-audit.log`）/ SessionEnd |
| 记忆 | `[memory] enabled=true`；知识库 `~/.grok/memory/grok-code-7771c3f6/MEMORY.md` |
| Subagents | persona：`explorer`→flash（快读+codegraph）、`planner`→pro（架构规划） |
| 技能 | A 股数据 6 个 + Superpowers 14 个（仓库 `~/.grok/superpowers`，`git pull` 更新） |

> MCP/权限/hooks/personas 改动在**新会话**生效。验证：`grok mcp doctor`（2 healthy）、`grok inspect`（20 技能）。
